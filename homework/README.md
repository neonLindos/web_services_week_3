## Как запустить

```bash
cd homework
dotnet run
```

Откройте Swagger UI по адресу из вывода консоли.

## Что реализовано

- `IStudentService` / `StudentService` — сервис с in-memory списком из 3 студентов, зарегистрирован в `Program.cs` через `AddTransient<IStudentService, StudentService>()`.
- `StudentsController` получает `IStudentService` и `ILogger<StudentsController>` через Constructor Injection (без единого `new` внутри контроллера).

| Метод | Endpoint | Назначение | Успешный код | Код ошибки |
|---|---|---|---|---|
| GET | `/api/students` | получить список всех студентов | 200 OK | — |
| GET | `/api/students/{id}` | получить студента по Id | 200 OK | 400 Bad Request (Id ≤ 0) / 404 Not Found |

Логирование в `StudentsController`:

- `LogInformation` — при запросе списка студентов (`GetAll`);
- `LogWarning` — если студент с указанным Id не найден;
- `LogError` — если в запросе передан некорректный Id (≤ 0).

## Ответ на вопрос из методички

**В чём разница между Transient и Singleton и как изменение жизненного цикла может повлиять на работу приложения?**

`AddTransient` создаёт новый экземпляр сервиса при каждом запросе зависимости — для `StudentService` с in-memory списком это означает, что список студентов пересоздаётся заново при каждом обращении к контроллеру, и любые изменения (например, добавление студента в рамках одного запроса) не сохранятся между вызовами. `AddSingleton`, наоборот, создаёт единственный экземпляр на всё время жизни приложения — один и тот же список используется всеми запросами и всеми пользователями, поэтому изменения в нём сохраняются, но нужно следить за потокобезопасностью, если сервис не рассчитан на конкурентный доступ. Для этого учебного примера с константным набором данных разница не видна, но она становится критичной, как только сервис хранит изменяемое состояние.

## Контрольные вопросы

1. **Что такое Dependency Injection?** — паттерн, при котором зависимости объекта (сервисы, репозитории) не создаются им самим через `new`, а передаются извне — обычно через конструктор; управляет этим DI-контейнер фреймворка.
2. **Зачем использовать интерфейс вместо прямого создания объекта через `new`?** — код перестаёт зависеть от конкретной реализации, что упрощает замену реализации, unit-тестирование через моки/заглушки и снижает связанность между слоями.
3. **Что такое Constructor Injection?** — способ внедрения зависимостей, при котором они передаются через параметры конструктора класса; DI-контейнер сам подставляет нужные реализации при создании объекта.
4. **Для чего сервис регистрируется в `Program.cs`?** — чтобы DI-контейнер знал, какую конкретную реализацию (`StudentService`) подставлять, когда компонент запрашивает интерфейс (`IStudentService`), и с каким жизненным циклом её создавать.
5. **Для чего используется `ILogger<T>`?** — встроенный в ASP.NET Core механизм структурированного логирования; `T` определяет категорию (обычно — класс, из которого идёт запись), что упрощает фильтрацию логов по источнику.
6. **Чем отличаются `LogInformation`, `LogWarning` и `LogError`?** — уровни серьёзности сообщения: Information — обычное событие в штатной работе приложения; Warning — потенциальная проблема, не мешающая выполнению запроса; Error — произошла ошибка при обработке запроса.
