# Лабораторная работа — Модуль 03

**Тема:** Внедрение зависимостей (Dependency Injection. Логирование)
**Проект:** `ProductsLabApi` (Product)

## Как запустить

1. В Visual Studio создать проект **ASP.NET Core Web API** → имя `ProductsLabApi`.
2. Скопировать в проект содержимое папок `Models/`, `Services/`, `Controllers/`, а также `Program.cs` из этой директории.
3. Запустить и открыть Swagger.

## Что реализовано

- `IProductService` / `ProductService` — сервис с in-memory списком из 3 товаров (`GetAll`, `GetById`, `Add`, `Delete`), зарегистрирован через `AddScoped<IProductService, ProductService>()`.
- `ProductsController` получает `IProductService` и `ILogger<ProductsController>` через Constructor Injection.
- `Program.cs` дополнительно настраивает провайдеры логирования: `ClearProviders()` → `AddConsole()` → `AddDebug()`.

| Метод | Endpoint | Назначение | Успешный код | Код ошибки |
|---|---|---|---|---|
| GET | `/api/products` | получить список всех товаров | 200 OK | — |
| GET | `/api/products/{id}` | получить товар по Id | 200 OK | 404 Not Found |
| POST | `/api/products` | добавить товар | 201 Created | 400 Bad Request (пустой `Name`) |
| DELETE | `/api/products/{id}` | удалить товар | 200 OK | 404 Not Found / 400 Bad Request (Id ≤ 0) |

Логирование:

- `LogInformation` — при запросе списка, при успешном поиске по Id, при создании и при удалении товара;
- `LogWarning` — если товар с указанным Id не найден (в GetById и в Delete);
- `LogError` — дополнительное задание, см. ниже.

## Ответ на вопрос из методички

**Какие сообщения перестали отображаться после смены `Logging:LogLevel:Default` с `Information` на `Warning`, и почему?**

Перестают отображаться сообщения уровня `Information` (в частности, из `GetAll`, успешного `GetById`, `Create`, успешного `Delete`) — остаются только `Warning` и выше. Причина в том, что уровни логирования упорядочены по возрастанию серьёзности (`Trace < Debug < Information < Warning < Error < Critical`), а `LogLevel:Default` задаёт минимальный порог: всё, что строго ниже него, отбрасывается ещё до записи в провайдер.

**Transient vs Scoped vs Singleton (п. 11 методички):** `AddTransient` создаёт новый экземпляр `ProductService` при каждом внедрении — полезно для лёгких, не хранящих состояния сервисов (например, форматирование/валидация). `AddScoped` (использован в этом решении) создаёт один экземпляр на HTTP-запрос — подходит, когда несколько компонентов в рамках одного запроса должны видеть одно и то же состояние (например, единицу работы с БД). `AddSingleton` создаёт один экземпляр на всё время жизни приложения — подходит для действительно разделяемого, потокобезопасного состояния (кэш, конфигурация), но для `List<Product>` в памяти означает, что все пользователи видят и меняют один и тот же список, и нужно думать о конкурентном доступе.

## Дополнительное задание

Обработка исключения реализована в `Delete`: если передан `id ≤ 0`, метод выбрасывает `ArgumentOutOfRangeException`, который перехватывается в `catch`, логируется через `_logger.LogError(ex, "Error while processing product with ID {ProductId}", id)` и клиенту возвращается только `400 Bad Request` с общим текстом — без деталей исключения.

## Контрольные вопросы

1. **Что такое Dependency Injection?** — паттерн, при котором зависимости передаются объекту извне (обычно через конструктор), а не создаются им самим через `new`.
2. **Какую проблему решает DI?** — убирает жёсткую привязку компонента к конкретной реализации зависимости, упрощая замену реализации и тестирование через моки.
3. **Что такое слабая связанность компонентов?** — свойство кода, при котором компоненты знают друг о друге только через абстракции (интерфейсы), а не через конкретные реализации, что упрощает изменение одного без влияния на другие.
4. **Для чего используются интерфейсы при DI?** — задают контракт, независимый от реализации: контроллер работает с `IProductService`, не зная, что именно за ним стоит.
5. **Что такое Constructor Injection?** — способ внедрения зависимостей через параметры конструктора; DI-контейнер сам создаёт и подставляет нужные реализации.
6. **Для чего сервис регистрируется в `Program.cs`?** — чтобы DI-контейнер знал, какую реализацию подставлять для интерфейса и с каким жизненным циклом её создавать.
7. **Чем отличаются Transient, Scoped и Singleton?** — Transient — новый экземпляр на каждое внедрение; Scoped — один экземпляр на HTTP-запрос; Singleton — один экземпляр на всё время жизни приложения.
8. **Для чего используется `ILogger<T>`?** — встроенный механизм структурированного логирования; `T` задаёт категорию сообщений (обычно класс-источник).
9. **Чем отличаются Information, Warning и Error?** — Information — штатное событие; Warning — потенциальная проблема, не мешающая выполнению запроса; Error — произошла ошибка при обработке запроса.
10. **Для чего используется `appsettings.json` при настройке логирования?** — задаёт минимальный уровень логирования (`LogLevel`) по умолчанию и по отдельным категориям без изменения кода.
