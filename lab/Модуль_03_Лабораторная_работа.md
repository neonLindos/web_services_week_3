## Цель работы

Получить практические навыки применения Dependency Injection (DI) в ASP.NET Core, регистрации сервисов, использования Constructor Injection, выбора жизненного цикла зависимостей и организации логирования с помощью `ILogger<T>`.

## Задание

Разработать ASP.NET Core Web API для управления списком товаров с использованием Dependency Injection и логирования.

### 1. Создание проекта

Создайте новый проект ASP.NET Core Web API. Убедитесь, что доступен Swagger UI.

### 2. Создание модели

```csharp
public class Product
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
}
```

### 3. Создание интерфейса

`IProductService`:

```csharp
IEnumerable<Product> GetAll();
Product? GetById(int id);
Product Add(Product product);
bool Delete(int id);
```

### 4. Создание сервиса

`ProductService : IProductService`. Данные — обычный `List<Product>`, минимум 3 товара. База данных не требуется.

### 5. Регистрация сервиса

```csharp
builder.Services.AddScoped<IProductService, ProductService>();
```

Важно: `ProductService` не должен создаваться вручную через `new ProductService()` — этим занимается DI-контейнер.

### 6. Создание контроллера

`ProductsController` с `[ApiController]`, `[Route("api/[controller]")]`, внедрение `IProductService` через конструктор.

### 7. Реализация API

| HTTP | Маршрут | Назначение |
|---|---|---|
| GET | `/api/products` | Получить все товары |
| GET | `/api/products/{id}` | Получить товар по ID |
| POST | `/api/products` | Добавить товар |
| DELETE | `/api/products/{id}` | Удалить товар |

Успех — `200 OK` / `201 Created`; ошибка — `400 Bad Request` / `404 Not Found`.

### 8. Добавление логирования

`ILogger<ProductsController>` через конструктор вместе с сервисом. Шаблоны сообщений:

- GET список: `_logger.LogInformation("Getting all products");`
- GET по ID найден: `_logger.LogInformation("Product with ID {ProductId} was found", id);`
- GET по ID не найден: `_logger.LogWarning("Product with ID {ProductId} was not found", id);`
- POST создан: `_logger.LogInformation("Product {ProductName} was created", product.Name);`
- DELETE удалён: `_logger.LogInformation("Product with ID {ProductId} was deleted", id);`, если товара нет — `LogWarning`.

### 9. Настройка провайдеров логирования

```csharp
builder.Logging.ClearProviders();
builder.Logging.AddConsole();
builder.Logging.AddDebug();
```

### 10. Настройка уровня логирования

В `appsettings.json`, секция `Logging:LogLevel`, измените `Default` с `Information` на `Warning`. Ответьте: какие сообщения перестали отображаться и почему?

### 11. Исследование жизненного цикла DI

Последовательно смените регистрацию `IProductService` на `AddTransient`, `AddScoped`, `AddSingleton`. Для каждого варианта запустите и протестируйте API. Объясните разницу Transient → Scoped → Singleton, приведите по одному примеру применения каждого.

### 12. Тестирование через Swagger

1. `GET /api/products` — список товаров.
2. `GET /api/products/1` — существующий товар.
3. `GET /api/products/999` — 404 Not Found.
4. `POST /api/products` — создать товар.
5. Повторить GET и проверить результат.
6. `DELETE /api/products/{id}` — удалить товар.
7. Проверить сообщения в логах.

## Дополнительное задание

Добавьте обработку исключения в один из методов контроллера. При возникновении исключения запишите его через:

```csharp
_logger.LogError(
    ex,
    "Error while processing product with ID {ProductId}",
    id);
```

Клиенту при этом не следует передавать техническую информацию об исключении. API должен вернуть корректный HTTP-ответ об ошибке.
