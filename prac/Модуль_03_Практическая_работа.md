## Цель работы

На практике разобраться, как работает Dependency Injection (DI) в ASP.NET Core, научиться создавать сервисы, регистрировать их в DI-контейнере, внедрять зависимости через конструктор и использовать `ILogger<T>` для записи событий приложения.

## Шаг 1. Создаём проект

ASP.NET Core Web API. Запустите приложение и убедитесь, что проект работает и открывается Swagger.

## Шаг 2. Создаём модель

Папка `Models`, класс `Product`:

```csharp
public class Product
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
}
```

## Шаг 3. Создаём интерфейс сервиса

Папка `Services`, интерфейс `IProductService`:

```csharp
public interface IProductService
{
    IEnumerable<Product> GetAll();
    Product? GetById(int id);
}
```

*Обсудите:* почему контроллеру лучше работать с `IProductService`, а не напрямую с `ProductService`.

## Шаг 4. Создаём реализацию сервиса

В папке `Services` — `ProductService`:

```csharp
public class ProductService : IProductService
{
    private readonly List<Product> _products = new()
    {
        new Product { Id = 1, Name = "Laptop", Price = 350000 },
        new Product { Id = 2, Name = "Mouse", Price = 12000 },
        new Product { Id = 3, Name = "Keyboard", Price = 25000 }
    };

    public IEnumerable<Product> GetAll() => _products;

    public Product? GetById(int id) => _products.FirstOrDefault(p => p.Id == id);
}
```

На этом этапе обсудите цепочку: `Controller → IProductService → ProductService`.

## Шаг 5. Сначала создаём сильную связь

Для понимания проблемы временно создайте сервис непосредственно в контроллере:

```csharp
private readonly ProductService _service = new ProductService();

[HttpGet]
public IActionResult Get()
{
    return Ok(_service.GetAll());
}
```

Запустите приложение и проверьте метод через Swagger.

## Шаг 6. Убираем прямое создание объекта

Удалите `new ProductService()`. Контроллер теперь зависит от интерфейса:

```csharp
private readonly IProductService _service;

public ProductsController(IProductService service)
{
    _service = service;
}
```

Но пока **не регистрируйте** сервис в `Program.cs`. Запустите приложение.

*Наблюдение:* посмотрите, какую ошибку выдаст ASP.NET Core. *Обсудите:* почему DI-контейнер не смог создать `ProductsController`?

## Шаг 7. Регистрируем зависимость

В `Program.cs`:

```csharp
builder.Services.AddScoped<IProductService, ProductService>();
```

Теперь ASP.NET Core получает правило: если нужен `IProductService` → создать `ProductService`. Запустите приложение повторно и убедитесь, что ошибка исчезла.

## Шаг 8. Получаем все товары

```csharp
[HttpGet]
public IActionResult GetAll()
{
    return Ok(_service.GetAll());
}
```

В Swagger выполните `GET /api/products`, проверьте полученный JSON.

## Шаг 9. Получаем товар по ID

```csharp
[HttpGet("{id}")]
public IActionResult GetById(int id)
{
    var product = _service.GetById(id);

    if (product == null)
        return NotFound();

    return Ok(product);
}
```

Проверьте `GET /api/products/1` и `GET /api/products/100`, сравните ответы 200 OK и 404 Not Found.

## Шаг 10. Добавляем ILogger

Вторая зависимость контроллера:

```csharp
private readonly IProductService _service;
private readonly ILogger<ProductsController> _logger;

public ProductsController(
    IProductService service,
    ILogger<ProductsController> logger)
{
    _service = service;
    _logger = logger;
}
```

`ILogger<ProductsController>` отдельно регистрировать не требуется — инфраструктура логирования предоставляется ASP.NET Core.

## Шаг 11. Добавляем LogInformation

```csharp
[HttpGet]
public IActionResult GetAll()
{
    _logger.LogInformation("Getting all products");
    return Ok(_service.GetAll());
}
```

Выполните запрос через Swagger, найдите сообщение в консоли/Output.

## Шаг 12. Добавляем LogWarning

```csharp
[HttpGet("{id}")]
public IActionResult GetById(int id)
{
    var product = _service.GetById(id);

    if (product == null)
    {
        _logger.LogWarning("Product with ID {ProductId} was not found", id);
        return NotFound();
    }

    _logger.LogInformation("Product with ID {ProductId} was found", id);
    return Ok(product);
}
```

Выполните `GET /api/products/1`, затем `GET /api/products/100`, найдите соответствующие записи в журнале.

## Шаг 13. Проверяем уровни логирования

Временно добавьте все уровни:

```csharp
_logger.LogTrace("Trace message");
_logger.LogDebug("Debug message");
_logger.LogInformation("Information message");
_logger.LogWarning("Warning message");
_logger.LogError("Error message");
_logger.LogCritical("Critical message");
```

Запустите приложение, посмотрите, какие сообщения отображаются. Откройте `appsettings.json`:

```json
"Logging": {
  "LogLevel": {
    "Default": "Information"
  }
}
```

Измените `Information` на `Warning`, повторите запрос. *Обсудите:* почему сообщения Information больше не отображаются, а Warning и Error продолжают отображаться?

## Итоговая схема

```
HTTP Request
  ↓
ProductsController
  ↓
IProductService
  ↓
DI Container
  ↓
ProductService
  ↓
List<Product>
```

Параллельно: `ProductsController → ILogger → Log`.
